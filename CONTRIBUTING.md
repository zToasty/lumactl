# Правила разработки (Contributing)

Мы рады любой помощи в развитии lumactl! Чтобы процесс разработки был комфортным и безопасным для всех, мы придерживаемся простого Git Flow.

## Архитектура
Каждый новый режим подсветки (анимация, захват экрана) должен быть реализован как отдельная структура в папке internal/effects/ и строго соответствовать интерфейсу Effect (см. effect.go). 

## Как вносить изменения

1. Ветка main защищена. Прямые пуши (коммиты) в основную ветку запрещены. 
2. Создавайте ветки. Для каждой новой фичи или эксперимента создавайте отдельную ветку. Формат названия: feature/название-фичи (например, feature/ambient-capture).
3. Пишите код и тестируйте. Локально в своей ветке можно делать что угодно.
4. Pull Request (PR). Когда логика готова (или если нужен совет по коду), открывайте PR в ветку main.
5. Ревью. Код попадает в проект только после аппрува (одобрения) других контрибьюторов.

## Стиль кода
Проект использует стандартное форматирование Go. Перед коммитом желательно выполнять команду:

go fmt ./...
