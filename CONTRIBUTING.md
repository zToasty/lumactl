# Правила разработки (Contributing Guidelines)

Мы рады любой помощи в развитии `lumactl`! Чтобы процесс разработки был комфортным, а основная ветка оставалась стабильной, мы придерживаемся следующих правил.

## 🏗 Архитектура
Все новые режимы подсветки и анимации должны:
1. Располагаться в директории `internal/effects/`.
2. Строго соответствовать интерфейсу `Effect` из файла `effect.go`.
3. Быть изолированными (не ломать логику других эффектов).

## 🌿 Работа с ветками (Git Flow)
Прямые пуши в ветку `main` запрещены. Вся работа ведется в тематических ветках:

- **feature/** — новые функции (например, `feature/ambient-capture`)
- **fix/** — исправление ошибок (`fix/usb-connection`)
- **docs/** — обновление документации (`docs/readme-update`)
- **refactor/** — изменение структуры кода без смены функционала

### Жизненный цикл задачи:
1. Создайте ветку от актуального `main`.
2. Напишите код и протестируйте его локально.
3. Отправьте ветку в репозиторий (`git push origin feature/name`).
4. Откройте **Pull Request (PR)** в ветку `main`.
5. Дождитесь код-ревью и аппрува от владельца репозитория.
6. После слияния (Merge) ветку в GitHub можно удалять.

## 💬 Сообщения коммитов (Conventional Commits)
Для чистоты истории используйте префиксы:
- `feat: ...` — новая фича.
- `fix: ...` — исправление бага.
- `docs: ...` — документация.
- `chore: ...` — рутинные задачи (настройка конфигов, гит-игнора).

Пример: `feat: implement frame calculation for rainbow effect`

## 🛠 Стиль кода
Перед созданием PR обязательно отформатируйте код стандартной утилитой:
`go fmt ./...`
